# OpenClaw Agent Integration Implementation Plan

## 1. Objectives

Based on `XIAOZHI_OPENCLAW_PROTOCOL.md`, implement OpenClaw integration in `xiaozhi-esp32-server-golang` with the following requirements:

1. Console does not add independent OpenClaw configuration page.
2. OpenClaw endpoint generation method is consistent with MCP endpoint (generated by agent, token contains `user_id`, `agent_id`).
3. Main program manages OpenClaw WebSocket connections by `agent_id`.
4. Device configuration sends OpenClaw configuration via struct (enable flag + enter/exit keywords).
5. After ASR, support entering/exiting OpenClaw mode; messages in mode bypass LLM, go directly to OpenClaw, then to TTS.
6. When OpenClaw response arrives late and device is offline, enter memory offline queue; replay when device comes online next time.
7. Offline queue policy: max 20 messages per device, TTL 24 hours.

## 2. Console Modifications (manager backend)

### 2.1 Agent Field Extensions

Extend `models.Agent`:

- `OpenclawEnabled bool`
- `OpenclawEnterKeywords string` (JSON array string)
- `OpenclawExitKeywords string` (JSON array string)

Notes:

- Do not add independent OpenClaw endpoint configuration table.
- Endpoint retrieval logic aligns with MCP: dynamically generated and returned via agent interface.

### 2.2 Endpoint Interface

New interfaces (user and admin):

- `GET /api/user/agents/:id/openclaw-endpoint`
- `GET /api/admin/agents/:id/openclaw-endpoint`

Behavior:

1. Validate agent exists and ownership is legitimate.
2. Read OTA external WebSocket URL.
3. Generate stable JWT token (long-term valid, no exp/iat set).
4. Return `ws(s)://host/ws/openclaw?token=<token>`.

### 2.3 Token Claims

New OpenClaw claims:

- `user_id`
- `agent_id`
- `endpoint_id` (`agent_<agentID>`)
- `purpose=openclaw-endpoint`

## 3. Device Configuration Delivery and Parsing

### 3.1 Struct

Add to main program `UConfig`:

```go
type OpenClawConfig struct {
    Allowed       bool     `json:"allowed"`
    EnterKeywords []string `json:"enter_keywords"`
    ExitKeywords  []string `json:"exit_keywords"`
}
```

And add to `UConfig`:

```go
OpenClaw OpenClawConfig `json:"openclaw"`
```

### 3.2 /api/configs Response

Admin `GetDeviceConfigs` adds:

```json
"openclaw": {
  "allowed": true,
  "enter_keywords": ["enter claw mode", "openclaw"],
  "exit_keywords": ["exit claw mode", "exit openclaw"]
}
```

Population rules:

1. `allowed = agent.openclaw_enabled`
2. `enter_keywords/exit_keywords` parsed from agent fields as JSON array
3. If field is empty or parsing fails, fallback to empty array

### 3.3 Main Program Configuration Retrieval

`ConfigManager.GetUserConfig` parses `openclaw` object, writes to `types.UConfig.OpenClaw`.

## 4. Main Program OpenClaw WebSocket Server

### 4.1 Route

New route:

- `/ws/openclaw`

### 4.2 Connection Dimension

Manage connection pool by `agent_id`:

- key: `agentID`
- value: OpenClaw session (single connection)

Replace old connection when new connection is established, ensuring only one active OpenClaw WS connection per agent.

### 4.3 Protocol Handling

1. Send `handshake_ack` after connection establishment
2. Reply `pong` when receiving `ping`
3. When receiving `response`:
   - Find device route by `correlation_id`
   - Push TTS if device is online
   - Write to offline queue if device is offline
4. Log when receiving `error/close` and clean up by session

## 5. Chat Flow Modifications

### 5.1 Session State

`ClientState` adds OpenClaw runtime state:

- `OpenClawMode bool`

### 5.2 ASR Post-Diversion

Add flow in `ChatSession.actionDoChat`:

1. Recognize exit keywords (highest priority)
2. Recognize enter keywords
3. If currently in OpenClaw mode:
   - Send text directly to OpenClaw
   - Do not call LLM
4. If not in OpenClaw mode:
   - Keep original LLM flow

Keyword matching method: First normalize text (trim leading/trailing whitespace, common punctuation), then `contains` match.

## 6. Offline Message Queue

Add memory offline queue manager:

- key: `deviceID`
- value: `[]OfflineMessage`
- Fields per record: `Text`, `CreatedAt`, `CorrelationID`

Policy:

1. Max 20 messages per device (drop oldest when exceeded)
2. TTL 24h (dual cleanup on write and read)
3. Auto replay when device comes online and clear successfully sent messages

Online trigger point:

- After device is online in `App.OnNewConnection`, trigger offline message replay for that device

## 8. Installation Steps (Including Channel Configuration)

1. Install xiaozhi OpenClaw plugin:
   `openclaw plugins install @xiaozhi_openclaw/xiaozhi`
2. Open agent OpenClaw configuration in console, copy that agent's OpenClaw access point (`ws(s)://.../ws/openclaw?token=...`).
3. Execute "configure channel" in OpenClaw session:
   - Send the access point from previous step directly to OpenClaw
   - Explicitly tell it: `configure xiaozhi channel plugin`
4. After configuration is complete, use test session to send a message, confirm can receive OpenClaw response.

## 9. Verification Checklist

1. Console can retrieve OpenClaw endpoint (consistent with MCP generation logic).
2. `/api/configs` returns structured `openclaw` field.
3. OpenClaw client can establish connection and handshake via `/ws/openclaw`.
4. Enter keywords can switch to OpenClaw mode, exit keywords can exit mode.
5. Messages in OpenClaw mode bypass LLM, responses can be converted to TTS.
6. When device is offline, responses enter offline queue; replayed when online.
7. Offline queue satisfies 20 message limit and 24 hour TTL.
